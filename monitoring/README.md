# Velo Monitoring (Prometheus + Grafana)

Grafana dashboards for a Velo **singleton or cluster**, plus the Prometheus
scrape config and a small relay that makes Velo's metrics scrapeable.

## Quick start

```bash
cd monitoring
./run.sh                 # starts relay + Prometheus + Grafana, generates dashboards
# Grafana:    http://localhost:13000   (anonymous admin; or admin/admin)
# Prometheus: http://localhost:19090
./run.sh stop
```

Point `prometheus.yml` at your Velo instance(s) first (default `127.0.0.1:7379`).

## Why the relay?

Velo parses its HTTP query string **positionally, with no `=`**:

- global metrics: `GET /?metrics`
- per-slot metrics: `GET /?manage&slot&0&view-metrics`

Prometheus always URL-encodes scrape params as `key=value` and sorts them, so a
direct scrape (`/?metrics=`) returns **404**. `velo_slot_relay.py` is a tiny
multi-target exporter that Prometheus scrapes normally; it fetches the exact
positional URL Velo expects and returns the text unchanged (global) or with
Velo's own `{slot="N"}` label stripped (per-slot).

```
Prometheus ──/metrics?target=host:7379[&slot=0|last]──► relay ──►  Velo
                                                          (:9200)   (:7379)
```

Per-slot metrics require this because `oneSlot.collect()` must run on that
slot's own worker thread (thread-local, run-to-completion), which is why Velo
routes it through the `manage` command instead of the shared default registry.

## Scrape jobs (`prometheus.yml`)

| job              | Velo URL via relay                 | `slot` label |
|------------------|------------------------------------|--------------|
| `velo-global`    | `/?metrics`                        | –            |
| `velo-slot0`     | `/?manage&slot&0&view-metrics`     | `0`          |
| `velo-slot-last` | `/?manage&slot&<N-1>&view-metrics` | `last`       |

Per-slot panels intentionally cover only **slot 0 and the last slot**
(`slotNumber-1`); the last index is resolved per instance by the relay, so a
heterogeneous cluster still labels the series `slot="last"`. Each job lists
Velo instances under `targets:` and relabels the scrape address to the relay,
passing the real instance in `__param_target` (and `slot` from `__param_slot`).
Add cluster instances by adding lines to each job's `targets:`.

## Dashboards

Generated by `gen_dashboard.py` into `grafana/dashboards/` (and mirrored to
`../doc/metrics/`). Regenerate after editing the script: `python3 gen_dashboard.py`.

Panels are grouped into rows by **the question an operator is asking**, not by
the code module that emits the metric. The global/per-slot split at the
dashboard level follows the hard technical boundary (global metrics have no
`slot` label; per-slot metrics come from the relay jobs for slot 0 & last).
Static config/tuning metrics are intentionally omitted.

- **Velo — Global** (`$instance`) — rows:
  `Overview` (uptime, QPS, p99, clients, heap, cpu, compression ratio, total
  keys) · `Commands & Traffic` (per-command QPS & latency quantiles, net I/O,
  clients) · `Compression & Dict` · `Runtime (JVM & OS)` (heap, GC, RSS, load,
  fds).
- **Velo — Slot Capacity & Persistence** (`$instance`,`$slot`) — rows:
  `Capacity` (will I run out: key counts, disk breakdown, chunk fill rate,
  segment used/reusable/cursor, bucket count, TTL) · `Persist I/O & Latency`
  (is storage fast: `fd_k`/`fd_c` read/write latency & throughput, WAL persist
  rate, FD op rates).
- **Velo — Slot Cache / Compression / Replication** (`$instance`,`$slot`) —
  rows: `Cache & LRU` (LRU hit ratio/rates/count, WAL hit, FD page-cache LRU) ·
  `Per-FD Compression` (after-read compress ratio & cost, decompress time) ·
  `Big Values` (big keys, big-string files) · `Replication` (slave link/lag/
  offsets, master repl pair, binlog, last seq).

Replication panels are empty on a non-replicating singleton (metrics are only
emitted when a slot has a repl pair).

## Ports

Chosen to avoid collisions on the dev host: relay `9200`, Prometheus `19090`,
Grafana `13000`. Change them in `docker-compose.yml`, `prometheus.yml`
(relay `replacement:`), and `grafana/provisioning/datasources/datasource.yml`.
