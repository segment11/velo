# Velo Monitoring (Prometheus + Grafana)

Grafana dashboards for a Velo **singleton or cluster**, plus the Prometheus
scrape config. Prometheus scrapes Velo directly — no relay.

## Quick start

```bash
cd monitoring
./run.sh                 # starts Prometheus + Grafana, generates dashboards
# Grafana:    http://localhost:13000   (anonymous admin; or admin/admin)
# Prometheus: http://localhost:19090
./run.sh stop
```

Point `prometheus.yml` at your Velo instance(s) first (default `127.0.0.1:7379`).

## How Prometheus scrapes Velo directly

Velo parses its HTTP query **positionally** (global metrics `GET /?metrics`,
per-slot `GET /?manage&slot&0&view-metrics`). Prometheus can only emit
`key=value` params, so Velo also accepts those by keeping **only the value
part** of each token. A single repeated key `arg` reproduces the positional
command, because Prometheus preserves value order within one key:

```yaml
params: {arg: [metrics]}                            # -> GET /?arg=metrics
params: {arg: [manage, slot, '0', view-metrics]}    # -> GET /?arg=manage&arg=slot&arg=0&arg=view-metrics
```

Each Velo instance is scraped directly, so `__address__` is already the
instance (`instance` label is automatic) and per-slot output carries Velo's own
`{slot="N"}` label — no relabeling needed.

Per-slot metrics go through the `manage` command (not the shared default
registry) because `oneSlot.collect()` must run on that slot's own worker thread
(thread-local, run-to-completion).

## Scrape jobs (`prometheus.yml`)

| job              | Velo URL scraped                   | `slot` label   |
|------------------|------------------------------------|----------------|
| `velo-global`    | `/?arg=metrics`                    | –              |
| `velo-slot0`     | `/?arg=manage&arg=slot&arg=0&...`  | `0` (from Velo) |
| `velo-slot-last` | `/?arg=manage&arg=slot&arg=<N-1>&...` | `N-1` (from Velo) |

Per-slot panels intentionally cover only **slot 0 and the last slot**
(`slotNumber-1`). Direct scraping has no way to resolve the last index per
instance, so set the last-slot job's index explicitly to `slotNumber-1` (the
default `slotNumber=1` makes it equal `velo-slot0`; drop the job or bump the
index once you run more slots). The series is labelled by Velo's own
`{slot="N"}`. Add cluster instances by adding lines to each job's `targets:`.

## Dashboards

Generated by `gen_dashboard.py` into `grafana/dashboards/` (and mirrored to
`../doc/metrics/`). Regenerate after editing the script: `python3 gen_dashboard.py`.

Panels are grouped into rows by **the question an operator is asking**, not by
the code module that emits the metric. The global/per-slot split at the
dashboard level follows the hard technical boundary (global metrics have no
`slot` label; per-slot metrics come from the slot 0 & last scrape jobs).
Static config/tuning metrics are intentionally omitted.

- **Velo — Global** (`$instance`) — rows:
  `Overview` (uptime, QPS, p99, clients, heap, cpu, compression ratio, total
  keys) · `Commands & Traffic` (per-command QPS & latency quantiles, net I/O,
  clients) · `Compression & Dict` · `Runtime (JVM & OS)` (heap, GC, RSS, load,
  fds).
- **Velo — Slot Capacity & Persistence** (`$instance`,`$slot`) — rows:
  `Capacity` (will I run out: key counts, disk breakdown, chunk fill rate,
  segment used/reusable/cursor, bucket count, TTL) · `Persist I/O & Latency`
  (is storage fast: `fd_k`/`fd_c` read/write latency & throughput, WAL persist
  rate, FD op rates).
- **Velo — Slot Cache / Compression / Replication** (`$instance`,`$slot`) —
  rows: `Cache & LRU` (LRU hit ratio/rates/count, WAL hit, FD page-cache LRU) ·
  `Per-FD Compression` (after-read compress ratio & cost, decompress time) ·
  `Big Values` (big keys, big-string files) · `Replication` (slave link/lag/
  offsets, master repl pair, binlog, last seq).

Replication panels are empty on a non-replicating singleton (metrics are only
emitted when a slot has a repl pair).

## Ports

Chosen to avoid collisions on the dev host: Prometheus `19090`, Grafana
`13000`. Change them in `docker-compose.yml` and
`grafana/provisioning/datasources/datasource.yml`.
